## Overview

**رکاد (Rokad)** — Iran's first startup vocational high-school (هنرستان استارتاپی). A marketing landing page built with Vite + React 18 + Tailwind CSS, fully RTL (Persian/Farsi), targeting parents and students.

**Brand personality:** playful, energetic, anti-cookie-cutter, trustworthy, youth-oriented ed-tech.

**Visual signature:**
- Paper-collage / sticker aesthetic — every card, heading word, and button independently rotated ±1–3°
- Word-by-word headline composition (each word is its own absolutely-positioned, independently rotated `<span>`)
- Two-layer offset card shadows — a solid accent-color duplicate rect offset 4–6px down-right behind the front card (never CSS `box-shadow`)
- Asymmetric cut-corner squircle radius — `rounded-tl-*` + `rounded-br-*` with other two corners square — the single most repeated shape motif
- Color-coded audience segmentation: navy = boys track, magenta = girls track, teal = brand/CTA, orange = tertiary accent

**Tech stack:** React 18, Vite 8, Tailwind CSS 3, Swiper 14, React Router DOM 6. Fonts: self-hosted IRANSansX (11 weights) + Montserrat variable.

## Layout & Spacing

- **Canvas:** 1440px desktop reference frame.
- **Content column:** 1200px (`max-w-[75rem]`), centered → 120px fixed side margins at desktop (`xl:` breakpoint).
- **Responsive breakpoints:** `xs` (420px), `sm` (640px), `md` (768px), `lg` (1024px), `xl` (1280px), `2xl` (1536px).
- **Section vertical rhythm:** `py-[4rem]` mobile → `py-[5rem]` tablet → `py-[6rem]` desktop. Some sections use `section-sm` (3rem) or `section-xl` (8rem) variants.
- **Gutter tokens:** `gutter` (3rem), `gutter-md` (4rem), `gutter-lg` (6rem), `gutter-xl` (7.5rem).
- **Card gap:** `gap-[1rem]` mobile → `gap-[1.5rem]` tablet → `gap-[2rem]` desktop (varies by section).

**RTL rule:** `dir="rtl"` on `<html>` and explicit `direction: rtl` on `html`/`body` in `index.css`. Under RTL, the **first child in a flex/grid row renders at the right edge** — all data arrays are ordered with that in mind.

**⚠️ Layout gotcha:** The `Container` component uses `max-w-[75rem]` (1200px). Every section wraps content in `<Container>`. Sections that need full-bleed backgrounds apply the color to the `<section>` itself, while content stays inside Container.

## Elevation

### Two-Layer Offset-Rect Shadow (signature technique)

Every "sticker card" uses this exact pattern:

```jsx
{/* Back shadow layer */}
<div
  aria-hidden="true"
  className="absolute top-[0.1875rem] left-[0.1875rem] w-full h-full bg-[#292827] rounded-[...]"
/>
{/* Front card layer */}
<div className="relative z-10 bg-white border-2 border-[#292827] rounded-[...]">
  {content}
</div>
```

**Offsets by component:**
- StatCard: `top-2 left-2 -right-[0.25rem] -bottom-[0.25rem]` (≈4px)
- SchoolCard: `top-[0.3rem] left-[0.3rem]` (≈5px)
- PillarCard (light): `top-[0.3rem] left-[0.3rem]` (≈5px)
- FAQ accordion: `top-[0.3125rem] left-[0.3125rem]` (5px)
- Honors card: `top-[0.1875rem] left-[0.1875rem]` (3px)
- Comments card: `top-[0.125rem] left-[0.125rem]` (2px) mobile → `top-[0.25rem] left-[0.25rem]` (4px) desktop
- BlogCard: `top-[0.25rem] left-[0.25rem]` (4px)
- StudentCard: `top-[0.3rem] left-[0.3rem]` (5px) mobile → `top-[0.3125rem] left-[0.3125rem]` (5px) desktop

**Shadow color:** almost always `bg-[#292827]` (ink) or the card's accent color. The offset direction is always `top/left` (RTL-correct: shadow falls down-right).

### Navbar Shadow

shadow-[0_0.0625rem_0.1875rem_rgba(0,0,0,0.04),0_0.5rem_1.25rem_rgba(33,41,90,0.05),0_1.25rem_2.5rem_-0.25rem_rgba(33,41,90,0.06)]

### Icon Button Pattern (carousel nav arrows)

Every carousel navigation button follows this exact two-layer pattern:

```jsx
<div className="relative">
  {/* Shadow layer */}
  <div
    aria-hidden="true"
    className="absolute top-[0.125rem] left-[0.1875rem] w-full h-full bg-[#292827] rounded-[0_0.853125rem_0_0.853125rem] [corner-shape:squircle]"
  />
  {/* Button */}
  <button className="relative w-12 h-12 ... rounded-[0_0.853125rem_0_0.853125rem] [corner-shape:squircle] ...">
    <ChevronLeftIcon />
  </button>
</div>
```
- Shadow offset: `top-[0.125rem] left-[0.1875rem]`
- Radius: `rounded-[0_0.853125rem_0_0.853125rem]` (asymmetric)
- Button bg: `bg-white`, border: `border-[#292827] 0.125rem`
- Hover: `hover:-translate-y-0.5`

### Button Pattern (filled with offset shadow)

```jsx
<div className="relative inline-flex ... -rotate-[1.55deg] hover:rotate-0 transition-all duration-300">
  {/* Shadow layer */}
  <div aria-hidden="true" className="absolute top-[0.125rem] left-[0.125rem] w-full h-full bg-[#21295A] rounded-[...]" />
  {/* Button */}
  <a className="relative z-10 bg-white border-[0.125rem] border-[#21295A] ...">
    {label}
  </a>
</div>
```

### Button Pattern (outline with fill-on-hover background-image trick)

Used on "همه افتخارات" and "همه مقالات" buttons:

```jsx
className="[background-image:linear-gradient(to_right,#21295A,#21295A)] bg-no-repeat [background-size:0%_100%] hover:[background-size:100%_100%] hover:text-white transition-all duration-300 ease-out"
```
White border + white text → on hover, a gradient fills from right to left (RTL-correct), text turns white.

## Do's and Don'ts

### Do
- **Do** use `dir="rtl"` on `<html>` and `direction: rtl` on `html`/`body` in CSS — never rely on per-node `dir="auto"`.
- **Do** order all data arrays with RTL in mind — first element renders at the **right** edge.
- **Do** use the two-layer offset-rect shadow technique for all sticker cards. Never use CSS `box-shadow` for card shadows — the hard edge is a brand signature.
- **Do** snap rotation values to the scale: `-3, -1.5, 0, +1.5, +2, +2.5, +3` degrees. Don't use hand-placed floats like `1.83deg`.
- **Do** render semantic headings as single accessible DOM nodes and apply per-word rotation via `<span>` wrappers.
- **Do** use `font-weight: 950` (ExtraBlack) directly in inline styles when Tailwind's utility set doesn't expose it — the design uses 950 frequently for headline words.
- **Do** use the `[corner-shape:squircle]` custom CSS property on every element that uses asymmetric cut-corner radius.
- **Do** apply the background pattern mask technique (`[mask-image:linear-gradient(...)]`) to every section that has a pattern overlay.
- **Do** use `overflow-x: clip` (not `hidden`) on carousel containers to allow cards to overflow their bounds while clipping the track.
- **Do** use `snap-x snap-mandatory` on horizontal scroll rails and `snap-center` on cards for mobile swipe experience.
- **Do** self-host all fonts — `IRANSansX` (11 weights) and `Montserrat` variable are in `public/fonts/`. Never use Google Fonts.
- **Do** use the two-dot translucent bullet (`rgba(255,255,255,0.58)` outer + `rgba(255,255,255,0.69)` inner, offset 2px) for feature chips on dark cards.
- **Do** use CSS grid row animation (`grid-rows-[0fr]` → `grid-rows-[1fr]`) for accordion open/close transitions — no JS animation needed.
- **Do** consolidate the near-duplicate navy hexes (`#21295a` / `#202a5a`) and teal hexes (`#58bdaf` / `#59bbaf`) to single tokens unless QA demands otherwise.

### Don't
- **Don't** hand-code character illustrations (hero mentor, boys student, girls student) as SVG — they are multi-part vector composites (50–150+ sub-shapes) that must be exported as flattened image assets.
- **Don't** use `box-shadow` for the offset card shadow — it looks softer and more generic than the hard-edge duplicate shape.
- **Don't** inline hex values in component JSX when a Tailwind theme token exists — use named tokens for maintainability.
- **Don't** leave Figma asset URLs in shipped code — they expire ~7 days after generation. Download and commit bytes immediately.
- **Don't** use `overflow: hidden` on carousel containers — use `overflow-x: clip` to allow card overflow while clipping the track.
- **Don't** forget that the Comments card radius **flips** between mobile (`rounded-[0_1.375rem_0_1.375rem]`) and desktop (`rounded-[2.5rem_0_2.5rem_0]`). This is intentional and must be preserved.
- **Don't** remove the `rotate-180` from background pattern images — they are intentionally flipped.
- **Don't** use `box-shadow` on the navbar — it uses a custom multi-layer shadow token defined in `tailwind.config.js`.
- **Don't** forget the `[corner-shape:squircle]` property on any asymmetric-radius element — it's part of the design system contract.
